## 📄 **Guardrails**


* **English:** Rules or boundaries set to control and guide the behavior of a system so it stays safe, correct, and within limits.
* **Urdu:** Wo qawaid ya hudood jo system ke behavior ko control karte hain taake wo safe, sahi aur hadon me rahe.


### **2. Why We Use Them**

* 🔹 **Safety** — Prevent harmful or unwanted behavior.
* 🔹 **Accuracy** — Keep responses or actions correct.
* 🔹 **Consistency** — Maintain a reliable standard.
* 🔹 **Compliance** — Follow rules or policies.


### **3. Types of Guardrails**

#### **1️⃣ Input Guardrails**

* **Definition:** Rules applied to the data or instructions coming **into** the system.
* **Purpose:** Stop unsafe, irrelevant, or invalid inputs before processing
* **Example:**

  * Rejecting an empty form submission
  * Blocking prompts with disallowed words
  * Validating email format before saving


#### **2️⃣ Output Guardrails**

* **Definition:** Rules applied to the data or responses **leaving** the system
* **Purpose:** Ensure final output is safe, relevant, and meets quality standards
* **Example:**

  * Removing personal information from AI responses.
  * Limiting answer length to 200 words.
  * Checking for harmful content before showing it

 
### **4. Input vs Output Guardrails**

| Feature        | Input Guardrails 🚪        | Output Guardrails 🚀            |
| -------------- | -------------------------- | ------------------------------- |
| **Applied On** | Incoming data/instructions | Outgoing data/responses         |
| **Purpose**    | Filter bad inputs          | Ensure safe and correct outputs |
| **Example**    | Email validation           | Remove harmful words            |
| **Timing**     | Before processing          | After processing                |



### **5. Summary**

* Guardrails = **Rules that keep the system safe and correct**.
* Input Guardrails → Stop bad data from entering.
* Output Guardrails → Stop bad results from leaving
